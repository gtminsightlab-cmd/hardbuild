# Internationalization audit — checks

**Purpose:** Check i18n and localization setup and coverage — the product renders correctly for every market it claims, and even for en-US only, dates, money, time zones and strings are handled so a second locale is a configuration change, not a rewrite.
**Scorecard row:** Internationalization · **Report:** `audits/i18n.md` · **Overlaps:** Legal (per-jurisdiction pages, disclosures), Copy & Content (string quality), Accessibility (`lang`, text resizing), SEO (hreflang, sitemap). Reference, don't repeat.

## Inputs to gather first
- `.hardbuild.json → audit.targetMarkets` (array of BCP-47 tags; default `["en-US"]`).
  **en-US only:** I18N-01, 02, 03, 04, 05, 10, 11, 13 still apply (locale-agnostic); I18N-06, 07, 08, 09, 12 are N/A ("single market") and I18N-02 reduces to "are strings centralised?". The area still yields a real score — state in the report header which checks were N/A and why.
- i18n library: `grep -E "next-intl|i18next|react-intl|@lingui|formatjs|next-international|paraglide" package.json`.
- Locale plumbing: `ls -d app/\[locale\] middleware.ts i18n.ts i18n/ messages/ locales/ 2>/dev/null`.
- Time/date handling: `grep -E "date-fns-tz|@date-fns/tz|dayjs|luxon|temporal-polyfill" package.json`; Supabase column types (`timestamptz` vs `timestamp` vs `date`).

## Checks
Format: `ID · weight · check · how to verify (strongest first) · typical failure`

- **I18N-01 · 2 · `<html lang>` is set and correct.**
  VERIFY: `curl -s <productionUrl> | grep -oE "<html[^>]*>"` → `lang="en"` (or `en-US`); with locale routing, `lang={locale}` and `dir="rtl"` for RTL locales. Else READ `app/layout.tsx` / `app/[locale]/layout.tsx`. `grep -rn "lang=\"" app --include=*.tsx` → no hardcoded `lang="en"` inside a `[locale]` tree.
  FAIL PATTERN: `<html lang="en">` on a Spanish page; `lang` missing entirely (screen readers mispronounce — cross-ref Accessibility).
- **I18N-02 · 2 · User-facing strings come from a message catalog (or are centralised).**
  VERIFY (library present): `grep -rnE "^\s*<(p|h[1-6]|span|button|label|option|a)[^>]*>[A-Za-z][^<{]{3,}<" app src components --include=*.tsx | grep -vE "\.(test|stories)\." | wc -l` → JSX literals (target 0); compare `jq 'paths(scalars)|length' messages/en.json` key count against `grep -rhoE "\bt\(['\"][a-zA-Z0-9_.]+['\"]" app src | sort -u | wc -l`; run the library's extract/lint if configured (`npx i18next-parser --dry-run`, `npx lingui extract --dry-run`). (No library, en-US only): PASS if error/toast/email copy lives in a module (`lib/copy.ts`, `constants/messages.ts`) and components import it; PARTIAL if only errors are centralised; FAIL if copy is scattered.
  FAIL PATTERN: `toast.error("Something went wrong")` in 40 files with six spellings.
- **I18N-03 · 3 · Dates, numbers and currency formatted with `Intl.*` or a library — never string concatenation.**
  VERIFY: `grep -rnE "toLocaleDateString\(\)|toLocaleString\(\)|\\$\{[^}]*\}\s*USD|\.toFixed\(2\)|'\\$' \+|\`\\$\$\{" app src components --include=*.ts --include=*.tsx` → each hit is a finding unless inside a shared formatter; confirm `lib/format.ts` (or equivalent) exports `formatCurrency`/`formatDate` built on `Intl.NumberFormat(locale, { style: 'currency', currency })` and `Intl.DateTimeFormat`/`date-fns format` with explicit locale. Premium, payroll and rate values must flow through the currency formatter — spot-check the quote/indication screen and PDF.
  FAIL PATTERN: `"$" + premium.toFixed(2)` → `$1234.5` on a quote PDF; `new Date(x).toLocaleDateString()` renders en-US on the server and the browser locale on the client → hydration mismatch.
- **I18N-04 · 3 · Time zones: store instants as `timestamptz` and render in the user's zone; calendar dates stay `date`.**
  VERIFY (SQL): `select table_name, column_name, data_type from information_schema.columns where table_schema='public' and data_type in ('timestamp without time zone','timestamp with time zone','date') order by 1,2;` → event times `timestamptz`, effective/expiration/DOB `date` (no time component), zero `timestamp without time zone`. Code: `grep -rnE "new Date\([a-zA-Z_.]*(effective|expir|start|end|dob|birth)[A-Za-z_]*\)" app src --include=*.ts --include=*.tsx` → `new Date('2026-01-01')` is UTC midnight and shifts a day in US zones = finding; expect `parseISO`+`format`, `Temporal.PlainDate`, or `date-fns/startOfDay` with explicit TZ. Vercel functions run `TZ=UTC` — user TZ must come from `profiles.timezone` or `Intl.DateTimeFormat().resolvedOptions().timeZone` on the client, never the server clock.
  FAIL PATTERN: policy effective date shows 12/31 for a 1/1 effective date because `date` was stored as `timestamp` and rendered in CST.
- **I18N-05 · 1 · Pluralisation handled, not `count + " items"`.**
  VERIFY: `grep -rnE "\} (item|record|quote|policy|policies|employee|result|agenc)[a-z]*\b|\+ ['\"]s['\"]|\(s\)" app src components --include=*.tsx | head -30`; with a library expect ICU `{count, plural, one {...} other {...}}`; without, `Intl.PluralRules` or one shared `pluralize()` helper.
  FAIL PATTERN: "1 policies", "quote(s)".
- **I18N-06 · 1 · RTL readiness (N/A unless an RTL locale is targeted).**
  VERIFY: `grep -rnoE "\b(ml|mr|pl|pr|left|right|text-left|text-right|rounded-[lr])-[0-9a-z\[\]]+" app src components --include=*.tsx | wc -l` vs logical utilities `(ms|me|ps|pe|start|end)-`; physical ones should be rare; `dir` set from locale; directional icons (chevrons, arrows) mirrored via `rtl:` variants.
  FAIL PATTERN: `pl-4` everywhere; chevrons pointing the wrong way in Arabic.
- **I18N-07 · 2 · Locale routing and detection (N/A for single market).**
  VERIFY: `app/[locale]/` segment exists; `middleware.ts` uses the library middleware with `locales`, `defaultLocale`, `localePrefix`; `curl -sI -H "Accept-Language: es" <productionUrl>/` → 307 to `/es` (or a stored cookie choice honoured); `curl -s -o /dev/null -w "%{http_code}" <productionUrl>/xx/pricing` → 404 not 500; locale switcher keeps the current path and persists via `NEXT_LOCALE` cookie.
  FAIL PATTERN: `/es` renders English under a Spanish URL; switching locale drops the user to `/`.
- **I18N-08 · 2 · Translated metadata and `hreflang` (N/A for single market).**
  VERIFY: `curl -s <productionUrl>/es | grep -oE '<link rel="alternate"[^>]+>'` → one per locale plus `x-default`; `generateMetadata` uses `getTranslations` for title/description; `curl -s <productionUrl>/sitemap.xml | grep -c "<xhtml:link"` > 0. Sitemap quality itself lives in SEO.
  FAIL PATTERN: English `<title>` on every locale; hreflang pointing only to itself.
- **I18N-09 · 2 · Fallback locale behaviour (N/A for single market).**
  VERIFY: `diff <(jq -r 'paths(scalars)|join(".")' messages/en.json | sort) <(jq -r 'paths(scalars)|join(".")' messages/es.json | sort)` → list missing keys per locale; READ library config (`onError`, `getMessageFallback`, `fallbackLng`): a missing key must render the default-locale string and log once — never the raw key, never a throw in production.
  FAIL PATTERN: `dashboard.quotes.title` shown as literal text; 500 on a missing namespace.
- **I18N-10 · 1 · UI tolerates text expansion (no fixed-width buttons/labels, no truncation of critical values).**
  VERIFY: `grep -rnoE "\bw-(\[[0-9]+px\]|[0-9]{1,2})\b" app src components --include=*.tsx | grep -iE "button|label|badge|tab" | head`; `truncate`/`line-clamp` on money, dates or status badges = finding. Browser: enable the library's pseudo-locale or zoom text to 150% and look for clipped buttons/overlapping nav. Even en-US: long agency names ("Lockton Companies of the Southwest, LLC") already exist.
  FAIL PATTERN: `w-24` on "Submit"; `truncate` on the premium column.
- **I18N-11 · 2 · Server and client agree on locale and time zone (no hydration mismatches).**
  VERIFY: `grep -rnE "toLocale(Date|Time)?String\(\)|Intl\.[A-Za-z]+Format\(\)|formatDistanceToNow\(" app src --include=*.tsx` → any call with no explicit locale/timeZone in a component that renders on both sides = finding; `grep -rn "suppressHydrationWarning" app components` → each use justified; locale passed to server components (`setRequestLocale`). Run `TZ=America/Chicago pnpm build && pnpm start`, open the dashboard in a browser set to another zone, console shows no "Text content did not match".
  FAIL PATTERN: relative dates ("2 hours ago") computed on server and client with different clocks, hidden with `suppressHydrationWarning`.
- **I18N-12 · 2 · Emails and SMS localised (N/A for single market).**
  VERIFY: send path reads `profiles.locale` and passes it to the template; `supabase/templates/` has per-locale variants or the Auth `send-email` hook picks by `user.user_metadata.locale`; SMS copy in Edge Functions comes from the catalog; money/dates in emails use the recipient's locale (cross-ref I18N-03).
  FAIL PATTERN: Spanish user gets an English password reset.
- **I18N-13 · 2 · Legal and regulatory pages per jurisdiction (headline only; detail in Legal).**
  VERIFY: for each target market a Terms/Privacy variant exists and the footer links the right one; state-specific insurance disclosures (CA vs TX licence lines) key off the account's state, not the browser locale (`grep -rn "state ===\|byState\[" components/legal app/\(legal\)`). en-US only: PASS if US pages exist and a single-jurisdiction statement is explicit.
  FAIL PATTERN: `/es/privacy` 404s; GDPR language on an en-US-only product with no EU processing (claim-vs-code → Legal).

## Scoring notes
- I18N-03 or I18N-04 failing on money or effective dates → CRITICAL (wrong premium shown, wrong coverage date = payment error / legal exposure). Everything else HIGH at most; I18N-05/06/10 are MEDIUM/LOW.
- en-US only: expect 8 applicable checks (01, 02, 03, 04, 05, 10, 11, 13). Never mark I18N-03/04 N/A because "we're US only" — the US has six time zones and DST; en-US still needs `Intl`.
- Library absent but a second market is claimed in `targetMarkets` or marketing copy: I18N-02, 07, 08, 09, 12 are FAIL (not N/A) because the market is promised.
- "To raise confidence": Supabase MCP/SQL for I18N-04 column types; production URL for I18N-01/07/08; a local `pnpm build && pnpm start` under a non-UTC `TZ` for I18N-11; `jq` for I18N-09 key diffs.
