# Database audit — checks

**Purpose:** Verify the database is structured well and working correctly — the schema enforces what the app assumes, tenants cannot see each other, migrations are the truth, and the data survives a bad day.
**Scorecard row:** Database · **Report:** `audits/database.md` · **Overlaps:** Security (SEC-05 RLS headline), Identity & Access (policy semantics per role), Cloud Cost (query/egress cost), Error Handling (DB error surfacing). Reference, don't repeat.

## Inputs to gather first
- Table inventory: Supabase MCP `list_tables` (schema `public`), or `grep -rnE "create table" supabase/migrations`.
- Migration folder: `ls supabase/migrations | wc -l`, newest file date; `supabase/seed.sql` presence.
- Generated types path: `grep -rln "Database = {" --include=*.ts src lib types supabase` (usually `types/supabase.ts` or `database.types.ts`).
- App query surface: `grep -rnE "\.from\(['\"][a-z_]+['\"]\)" --include=*.ts --include=*.tsx -o | sort | uniq -c | sort -rn` → which tables the app actually reads/writes.
- Tenant column name used by the app (`org_id`, `workspace_id`, `user_id`, `agency_id`) — pick it from the most-written tables.

## Checks
Format: `ID · weight · check · how to verify (strongest first) · typical failure`

- **DB-01 · 3 · RLS enabled on every public table.**
  VERIFY (Supabase MCP `execute_sql`): `select relname, relrowsecurity, relforcerowsecurity from pg_class c join pg_namespace n on n.oid=c.relnamespace where n.nspname='public' and relkind in ('r','p') order by 1;` → every row `relrowsecurity = true`. Also `select tablename from pg_tables where schemaname='public' and tablename not in (select tablename from pg_policies where schemaname='public');` → tables with RLS on but zero policies (deny-all: fine for service-role-only tables, a bug otherwise — list them). Else READ: `grep -rln "enable row level security" supabase/migrations` vs the `create table` list; any table created without a matching enable = FAIL.
  FAIL PATTERN: a late-added table (`audit_log`, `webhook_events`, `import_jobs`) created in a hotfix migration with no `alter table ... enable row level security`.
- **DB-02 · 3 · No permissive write policies; tenant column in every policy.**
  VERIFY: `select tablename, policyname, cmd, roles, qual, with_check from pg_policies where schemaname='public' and (cmd in ('INSERT','UPDATE','DELETE','ALL')) and (qual = 'true' or with_check = 'true' or qual is null and cmd <> 'INSERT');` → must be empty. Then `select tablename, policyname, qual, with_check from pg_policies where schemaname='public' and qual !~ '(auth\.uid\(\)|auth\.jwt\(\)|org_id|<tenant_col>)';` → each hit reviewed; a SELECT policy without a tenant/uid predicate on a tenant table is a cross-tenant read. Confirm `with_check` is set on INSERT/UPDATE (a `using` without `with_check` lets a user move a row into another tenant). Else READ `create policy` statements in migrations.
  FAIL PATTERN: `create policy "Enable read for authenticated" on quotes for select to authenticated using (true);` — every logged-in agency sees every agency's quotes.
- **DB-03 · 3 · Supabase advisors clean (security + performance).**
  VERIFY (MCP): `get_advisors(type='security')` → zero `ERROR`-level (e.g. `rls_disabled_in_public`, `security_definer_view`, `function_search_path_mutable`, `auth_users_exposed`); `get_advisors(type='performance')` → list `unindexed_foreign_keys`, `auth_rls_initplan` (policies calling `auth.uid()` per row instead of `(select auth.uid())`), `multiple_permissive_policies`, `unused_index`. Quote the counts. No MCP → UNCHECKED (cannot PASS), and name this as the top confidence raiser.
  FAIL PATTERN: `auth_rls_initplan` on every table — policies work but every query on a 50k-row table re-evaluates `auth.uid()` per row.
- **DB-04 · 2 · Primary keys on every table; FKs have deliberate ON DELETE.**
  VERIFY: `select c.relname from pg_class c join pg_namespace n on n.oid=c.relnamespace where n.nspname='public' and c.relkind='r' and not exists (select 1 from pg_constraint where conrelid=c.oid and contype='p');` → empty. `select conrelid::regclass, conname, confdeltype from pg_constraint where contype='f' and connamespace='public'::regnamespace;` → `confdeltype`: `a` (NO ACTION) is the default-you-forgot; each FK should be `c` (cascade: child rows like `quote_lines`), `n` (set null: optional refs like `assigned_to`), or `r` (restrict: protect billing/ledger rows). Cite FKs where the default clearly contradicts the data's meaning. Else READ `references ... on delete` in migrations.
  FAIL PATTERN: `profiles.id references auth.users(id)` with no `on delete cascade` → deleting a user in the dashboard fails or leaves an orphan profile.
- **DB-05 · 2 · Indexes on FKs and on hot WHERE/ORDER BY columns.**
  VERIFY: unindexed FKs: `select conrelid::regclass as tbl, a.attname from pg_constraint c join pg_attribute a on a.attrelid=c.conrelid and a.attnum=any(c.conkey) where c.contype='f' and not exists (select 1 from pg_index i where i.indrelid=c.conrelid and a.attnum=any(i.indkey));` → empty. Hot queries: `select calls, mean_exec_time, rows, left(query,120) from pg_stat_statements order by total_exec_time desc limit 15;` (if the extension is on — `select * from pg_extension where extname='pg_stat_statements'`); cross-check each top query's filter/sort columns against `pg_indexes`. Unused: `select indexrelname, idx_scan from pg_stat_user_indexes where idx_scan=0 and schemaname='public';`. Else READ: the app's `.eq(`/`.order(` columns per table (from Inputs) vs `create index` in migrations; every tenant column (`org_id`) needs an index because every RLS policy filters on it.
  FAIL PATTERN: `submissions(org_id)` has no index; every page load does a seq scan behind RLS.
- **DB-06 · 2 · `updated_at` maintained by trigger, not by the app.**
  VERIFY: `select c.relname from pg_class c join pg_attribute a on a.attrelid=c.oid where a.attname='updated_at' and c.relkind='r' and c.relnamespace='public'::regnamespace and not exists (select 1 from pg_trigger t where t.tgrelid=c.oid and not t.tgisinternal);` → tables with the column but no trigger. Confirm one shared function (`moddatetime` extension or `set_updated_at()`), not N copies. Else READ `create trigger ... before update` in migrations. N/A if no table has `updated_at` (then note it as a MEDIUM suggestion if there are mutable business tables).
  FAIL PATTERN: `updated_at timestamptz default now()` and the app sets it in 3 of 7 update paths.
- **DB-07 · 2 · NOT NULL and CHECK constraints match app assumptions.**
  VERIFY: for each table in the app query surface, compare the generated type (`Row` fields typed `string | null`) against how the app uses them (`row.email.toLowerCase()` on a nullable column = runtime crash or a constraint missing). `select table_name, column_name from information_schema.columns where table_schema='public' and is_nullable='YES' and column_name in ('org_id','user_id','email','status','amount','created_at');` → tenant and status columns must be NOT NULL. `select conrelid::regclass, pg_get_constraintdef(oid) from pg_constraint where contype='c' and connamespace='public'::regnamespace;` → statuses, amounts (`>= 0`), percentages, date ranges (`ends_at > starts_at`) should appear. Else READ `create table` bodies.
  FAIL PATTERN: `status text` with no check; the app switches on `'quoted' | 'bound'` and a typo `'Bound'` silently falls through.
- **DB-08 · 1 · Enums / lookup values consistent between DB and TypeScript.**
  VERIFY: `select t.typname, array_agg(e.enumlabel order by e.enumsortorder) from pg_type t join pg_enum e on e.enumtypid=t.oid group by 1;` vs the TS union in generated types and any hand-written `const STATUSES = [...]`/zod `z.enum([...])` (`grep -rnE "z\.enum\(|as const" --include=*.ts`). Each divergence is a finding; hand-written duplicates of a DB enum are a MEDIUM.
  FAIL PATTERN: DB enum has `cancelled`, zod schema has `canceled`.
- **DB-09 · 3 · Migrations are the source of truth — no drift.**
  VERIFY: `supabase db diff --linked` (or `supabase db diff --db-url "$SUPABASE_DB_URL"`) → "No schema changes detected". If the CLI is not linked: MCP `list_migrations` → the applied list must equal `ls supabase/migrations` (names and count); then spot-check 3 objects created in the last 5 migrations exist in `pg_class`/`pg_proc`/`pg_policies`, and spot-check 3 live policies/indexes have a migration that creates them (`git grep -n "<policyname>" supabase/migrations`). Any live object with no migration = dashboard edit = drift. Also `git log --oneline -5 -- supabase/migrations` to confirm migrations are committed, and that no migration file was edited after merge (`git log --follow -p` on the oldest few).
  FAIL PATTERN: a policy renamed in the dashboard ("Enable insert for users based on user_id") that exists nowhere in git; the next `db reset` drops it.
- **DB-10 · 2 · Generated types are current and used.**
  VERIFY: `supabase gen types typescript --linked --schema public > /tmp/types.ts && diff -q /tmp/types.ts <types path>` (or MCP `generate_typescript_types` and diff) → identical. `grep -rn "createClient<Database>" --include=*.ts` → the client is typed; `grep -rnE "\.from\([^)]*\) as any|as unknown as" --include=*.ts --include=*.tsx | wc -l` → casts that paper over stale types.
  FAIL PATTERN: types file last touched 4 months ago, 11 migrations since; `// @ts-expect-error` on every new column.
- **DB-11 · 1 · Delete strategy is consistent (soft vs hard).**
  VERIFY: `select table_name from information_schema.columns where column_name in ('deleted_at','is_deleted','archived_at') and table_schema='public';` → if any exist, every policy and app query on those tables filters them (`grep -rn "deleted_at" --include=*.ts` count vs `.from('<table>')` count), and FKs to soft-deleted parents are handled. If none exist, hard deletes must have `on delete` behavior (DB-04) and an audit trail where money/compliance rows are involved.
  FAIL PATTERN: `deleted_at` on `clients` but the list query and the `select` RLS policy never exclude it.
- **DB-12 · 3 · Tenant column present on every tenant table (and indexed, NOT NULL).**
  VERIFY: `select c.relname from pg_class c where c.relkind='r' and c.relnamespace='public'::regnamespace and not exists (select 1 from pg_attribute a where a.attrelid=c.oid and a.attname in ('org_id','user_id','<tenant_col>'));` → each listed table is either a global lookup (justify) or a FAIL. Child tables that reach the tenant only through a join (`quote_lines → quotes → org_id`) must have a policy that does that join or a denormalized column; cite which. Pair with DB-02 for the policy side.
  FAIL PATTERN: `attachments` keyed only by `quote_id`; policy checks `auth.uid() is not null`.
- **DB-13 · 3 · Backups / PITR adequate for the data's value.**
  VERIFY: dashboard → Database → Backups (needs user to grant access or screenshot): daily backups on Pro, PITR enabled if the app stores money/policy/compliance records or has writes users can't recreate. MCP `get_project` → plan tier; Free tier = no backups = FAIL for any production app with customer data. Also check a restore has been rehearsed (`docs/runbooks/*restore*` or README). Without access → UNCHECKED, cannot PASS.
  FAIL PATTERN: production app on Free tier with paying customers; "we'll upgrade later".
- **DB-14 · 2 · `security definer` functions reviewed, `search_path` pinned; seed data out of prod migrations.**
  VERIFY: `select p.proname, p.prosecdef, p.proconfig from pg_proc p where p.pronamespace='public'::regnamespace and (p.prosecdef or p.proconfig is null);` → every `prosecdef=true` function has `proconfig` containing `search_path=` and a reason to bypass RLS (e.g. `handle_new_user` trigger); `security definer` views (`select viewname from pg_views v join pg_class c on c.relname=v.viewname where relnamespace='public'::regnamespace and not (reloptions @> '{security_invoker=true}')` on PG15+) are a finding. Seeds: `grep -rlnE "insert into (public\.)?(profiles|orgs|users|plans)" supabase/migrations` → test rows/demo accounts in migrations = FAIL; they belong in `supabase/seed.sql`. Also `grep -rn "revoke execute\|grant execute" supabase/migrations` — RPCs exposed to `anon` by default (`PUBLIC` execute) should be revoked unless intentionally public.
  FAIL PATTERN: `create function admin_stats() security definer` with no `set search_path = public` and executable by `anon`.

## Scoring notes
- DB-01, 02, 03 (any security-advisor ERROR), 09, 12, 13 failing → CRITICAL findings (grade cap D). DB-14 is CRITICAL when a `security definer` function is callable by `anon`.
- Without Supabase MCP or a linked CLI, DB-01/02/04–08/12/14 can be READ from migrations (conf 85) but DB-03, 09 and 13 are UNCHECKED and must be FAIL or N/A, never PASS.
- A clean `get_advisors` result does not prove DB-02: advisors flag `using (true)` only on some patterns; still run the `pg_policies` query.
- "To raise confidence": Supabase MCP (`execute_sql`, `get_advisors`, `list_migrations`, `generate_typescript_types`), `supabase link` + `supabase db diff`, `pg_stat_statements` enabled, dashboard Backups page screenshot or plan tier.
