# Accessibility audit — checks

**Purpose:** Check that everyone can use your app — keyboard-only users, screen-reader users, people with low vision or motor impairments, and the owner himself, who needs large, high-contrast type. Target: WCAG 2.2 AA.
**Scorecard row:** Accessibility · **Report:** `audits/accessibility.md` · **Overlaps:** UX & Design (visual hierarchy, layout), Mobile (touch ergonomics beyond the 24px minimum), Error Handling (error *behavior*; here only how errors are *announced*), Performance (motion/animation cost). Reference, don't repeat.

## Inputs to gather first
- Route inventory: `find app -name "page.tsx" | sed 's|/page.tsx||' | sort` → pick the 5 highest-traffic pages (landing, sign-in, main dashboard, the primary form, settings) for browser checks.
- `.hardbuild.json → audit.productionUrl` (or `pnpm dev` on `http://localhost:3000`); if neither is reachable, every browser-based check is READ-only — say so.
- UI kit: `ls components/ui/` and `jq '.dependencies | keys | map(select(startswith("@radix-ui") or . == "cmdk" or . == "vaul" or . == "react-aria-components"))' package.json` → shadcn/Radix primitives give keyboard + aria for free; **custom** interactive components (`git grep -lE "onClick|onKeyDown" -- 'components/**/*.tsx' | grep -v components/ui/`) are where the problems live.
- Tooling present: `jq '.devDependencies | keys | map(select(test("axe|jsx-a11y|playwright|lighthouse")))' package.json`.

## Checks
Format: `ID · weight · check · how to verify (strongest first) · typical failure`

- **A11Y-01 · 3 · Automated scan passes with zero serious/critical violations.**
  VERIFY: `npx @axe-core/cli <url> --tags wcag2a,wcag2aa,wcag22aa --exit 2>&1 | tail -40` on each of the 5 pages; or if Playwright is installed, `npx playwright test tests/a11y.spec.ts` with `@axe-core/playwright` (`new AxeBuilder({ page }).analyze()`); or `npx lighthouse <url> --only-categories=accessibility --quiet --chrome-flags="--headless" --output=json | jq '.categories.accessibility.score'` → ≥0.95. Pages behind auth need a session — use Playwright `storageState` or test on `localhost` with a seeded user. If no URL at all: READ `eslint.config.*` for `eslint-plugin-jsx-a11y` (`next/core-web-vitals` includes a subset) and run `npx eslint . --rule '{"jsx-a11y/alt-text":"error"}' 2>&1 | grep -c jsx-a11y` → INFERRED only.
  FAIL PATTERN: axe reports `color-contrast` ×30 and `button-name` ×8 on the dashboard because every icon button is a bare `<Button size="icon">`.
- **A11Y-02 · 2 · Semantic landmarks and heading order.**
  VERIFY: in the browser `document.querySelectorAll('main,nav,header,footer,[role=main]').length` → exactly one `<main>` per page; headings: `[...document.querySelectorAll('h1,h2,h3,h4,h5,h6')].map(h=>h.tagName+': '+h.textContent.trim().slice(0,40))` → one `h1`, no level skipped. Else READ `app/layout.tsx` and the route-group layouts for `<main>`/`<nav aria-label>`; `git grep -cE "<h1" -- 'app/**/page.tsx'` should roughly equal the page count; `git grep -nE "<div[^>]*className=\"[^\"]*text-(3|4|5)xl" -- 'app/**' components/` → styled divs standing in for headings.
  FAIL PATTERN: `<div className="text-2xl font-bold">Dashboard</div>` as the page title; two `h1`s because the layout and the page both render one.
- **A11Y-03 · 2 · Every image has correct alt text.**
  VERIFY: `git grep -nE "<(Image|img)\b" -- '*.tsx' | grep -vE "alt=" ` → each hit is a finding (Next `<Image>` requires `alt`, but `alt=""` on meaningful images and `alt="image"`/`alt={fileName}` are also failures: `git grep -nE "alt=\{?['\"](image|img|photo|icon|logo)?['\"]\}?" -- '*.tsx'`). Decorative SVG icons need `aria-hidden="true"` — lucide icons inside a labeled button are fine; standalone ones are not: `git grep -nE "<[A-Z]\w+Icon\b[^>]*/>" -- '*.tsx' | grep -v aria-hidden | head`.
  FAIL PATTERN: user-uploaded avatars rendered with `alt={user.avatar_url}`; a chart image with `alt="chart"`.
- **A11Y-04 · 3 · Every form control has a programmatic label.**
  VERIFY: browser: `[...document.querySelectorAll('input,select,textarea')].filter(el=>!el.labels?.length && !el.getAttribute('aria-label') && !el.getAttribute('aria-labelledby') && el.type!=='hidden').map(el=>el.name||el.id||el.outerHTML.slice(0,80))` → empty. Code: `git grep -nE "<(Input|Select|Textarea|Checkbox|Switch|input|select|textarea)\b" -- '*.tsx' | grep -vE "aria-label|id=" | head -30`; for each `<Label>` check `htmlFor` matches an `id` (shadcn `FormLabel` inside `FormField` wires this automatically — custom forms do not). `placeholder` is not a label.
  FAIL PATTERN: `<Input placeholder="Email" />` with a visually adjacent `<p>Email</p>`; a search box with only a magnifying-glass icon.
- **A11Y-05 · 3 · Color contrast ≥4.5:1 for text, ≥3:1 for large text and UI boundaries.**
  VERIFY: axe `color-contrast` results from A11Y-01 are strongest. Then READ the tokens: `grep -nE "^\s*--(foreground|muted-foreground|primary|primary-foreground|secondary-foreground|destructive|border|ring|background|card)" app/globals.css` and compute each text/background pair (`npx wcag-contrast "#hsl→hex"` or the `polished` `getContrast` in a Node one-liner) for **both** `:root` and `.dark`. `--muted-foreground` on `--background` is the usual offender — shadcn's default (`215.4 16.3% 46.9%`) is 4.6:1 on white, but any "softening" breaks it. Check base font size: `git grep -nE "text-(xs|\[1[01]px\])" -- 'app/**' 'components/**' | wc -l` → `text-xs` (12px) for body or form copy is a finding; owner preference is ≥16px body with strong contrast. `html { font-size }` overrides below 100% are a FAIL.
  FAIL PATTERN: `text-xs text-muted-foreground/60` for table captions and help text — unreadable for the owner and under 3:1.
- **A11Y-06 · 3 · Focus is visible and follows a logical order; no keyboard traps.**
  VERIFY: browser: Tab through each of the 5 pages; focus ring must be visible on every stop and order must match the visual layout; a modal must trap focus inside and return it on close (Radix `Dialog` does; a custom one usually does not). Code: `git grep -nE "outline-none|focus:outline-none|outline:\s*none" -- '*.tsx' '*.css' | grep -vE "focus-visible:ring|focus-visible:outline" ` → each hit removes the ring without replacing it; `git grep -nE "tabIndex=\{?-?[1-9]" -- '*.tsx'` → positive tabindex is a finding; `autoFocus` inside a page body that steals focus from the skip link is a finding.
  FAIL PATTERN: global `*:focus { outline: none }` in `globals.css` "for aesthetics".
- **A11Y-07 · 3 · Custom interactive components are keyboard-operable with correct roles.**
  VERIFY: list custom interactives: `git grep -lE "onClick=" -- 'components/**/*.tsx' 'app/**/*.tsx' | xargs grep -lE "<(div|span|li|tr|td)\b[^>]*onClick" ` → each needs `role="button"` **and** `tabIndex={0}` **and** an `onKeyDown` for Enter/Space, or should be a `<button>`. Drag-and-drop, sliders, kanban cards, custom dropdowns, date pickers and data tables with row-click need a keyboard path — open each and confirm in the browser. Radix/shadcn primitives (`DropdownMenu`, `Dialog`, `Tabs`, `Select`, `Combobox` via `cmdk`) PASS by construction unless wrapped in a clickable `div`.
  FAIL PATTERN: `<tr onClick={() => router.push(...)}>` with no focusable child; a card grid where only the mouse can open an item.
- **A11Y-08 · 2 · Icon-only buttons and links have accessible names.**
  VERIFY: browser: `[...document.querySelectorAll('button,a')].filter(el=>!el.textContent.trim() && !el.getAttribute('aria-label') && !el.getAttribute('aria-labelledby') && !el.querySelector('[aria-label],title')).length` → 0. Code: `git grep -nE "<Button[^>]*size=\"icon\"" -- '*.tsx' | grep -v aria-label | head -30`; `git grep -nE "<(Link|a)\b[^>]*>\s*<[A-Z]\w+(Icon)?\s" -- '*.tsx' | grep -v aria-label`. Hidden text via `<span className="sr-only">` counts.
  FAIL PATTERN: the trash-can delete button, the `X` close button and the `⋯` row menu all announced as "button".
- **A11Y-09 · 2 · Async status and errors are announced via live regions.**
  VERIFY: toasts — `sonner`/shadcn `Toaster` renders `role="status"`/`aria-live` by default (PASS if used for all async feedback; verify `git grep -n "<Toaster" app/layout.tsx`). Inline: `git grep -nE "aria-live|role=\"(status|alert)\"" -- '*.tsx' | wc -l` vs. the number of loading/success states (`git grep -cE "isPending|isLoading|isSubmitting|useFormStatus" -- '*.tsx'`). Spinners need `role="status"` + `<span className="sr-only">Loading…</span>`; form submission errors need `role="alert"` (shadcn `FormMessage` does not add it — check).
  FAIL PATTERN: a silent spinner replaces the button text; the "Saved" state is a green checkmark icon only.
- **A11Y-10 · 1 · Motion respects `prefers-reduced-motion`.**
  VERIFY: `git grep -nE "prefers-reduced-motion|motion-reduce:|motion-safe:|useReducedMotion" -- '*.css' '*.tsx'` → at least one global guard or per-component usage; `git grep -nE "animate-(spin|bounce|pulse|ping)|framer-motion|animate\(" -- '*.tsx' | wc -l` to size the exposure. Tailwind `tailwindcss-animate` keyframes used by shadcn are short and acceptable; parallax, auto-playing carousels and infinite marquees are not without a guard. N/A if the app has no non-trivial animation.
  FAIL PATTERN: `framer-motion` page transitions on every route with no `useReducedMotion()` check.
- **A11Y-11 · 2 · Target size ≥24×24 CSS px (WCAG 2.2 SC 2.5.8).**
  VERIFY: browser: `[...document.querySelectorAll('button,a,[role=button],input[type=checkbox],input[type=radio]')].map(el=>({el:el.outerHTML.slice(0,60),...el.getBoundingClientRect()})).filter(r=>r.width<24||r.height<24)` → empty (or spacing exception documented). Code: `git grep -nE "size=\"(icon-sm|xs)\"|h-(4|5)\s+w-(4|5)\b.*(onClick|<Button)|h-5 w-5\"\s*/>\s*</(button|Button)" -- '*.tsx' | head`; shadcn `Checkbox` is 16px — acceptable only with a clickable `<Label>` extending the target. Mobile detail belongs in Mobile; here just the 2.2 minimum.
  FAIL PATTERN: 16px close icons in tag chips; 20px pagination arrows.
- **A11Y-12 · 1 · Skip link to main content.**
  VERIFY: browser: press Tab once on page load → a "Skip to main content" link becomes visible and moves focus to `<main id="main">` when activated. Code: `git grep -nE "skip to (main|content)|#main-content|#main\"" -- 'app/**/layout.tsx' 'components/**'` and `git grep -nE "id=\"main(-content)?\"" -- 'app/**'`. Must be the first focusable element in `app/layout.tsx`.
  FAIL PATTERN: no skip link, and 14 nav links before the first heading on every page.
- **A11Y-13 · 1 · Language attribute set (and changes marked).**
  VERIFY: `git grep -nE "<html[^>]*lang=" -- 'app/**/layout.tsx'` → `lang="en"` (or the real locale, driven by `next-intl`/`params.locale` if i18n). Browser: `document.documentElement.lang`. Mixed-language snippets need `lang` on the element. `<html>` without `lang` = FAIL.
  FAIL PATTERN: `<html>` with no `lang` because the scaffold was trimmed.
- **A11Y-14 · 2 · Form errors are identified, described, and suggest a fix.**
  VERIFY: submit each main form empty and with bad data in the browser: the invalid field must get `aria-invalid="true"`, the message must be tied via `aria-describedby`, focus should move to the first error (or a summary with `role="alert"`), and the text must say *what* to do ("Enter an email like name@company.com"), not just "Invalid". Code: shadcn `FormControl` sets `aria-invalid` + `aria-describedby` automatically — confirm forms use `FormField`/`FormControl` and not raw `<Input>` (`git grep -lE "useForm\(" -- '*.tsx' | xargs grep -L "FormControl"`). Zod messages: `git grep -nE "z\.(string|number)\(\)\.(min|email|regex)\([^)]*\)" -- '*.ts' '*.tsx' | grep -v "message\|{ *error" | head` → defaults like "Invalid email" or "String must contain at least 1 character(s)" are findings. Native `required` alone (browser bubble) is a PARTIAL.
  FAIL PATTERN: red border only, no text; a toast "Something went wrong" after validation failure with no field identified.

## Scoring notes
- A11Y-04, 06 or 07 failing on the sign-in, sign-up, checkout/quote or primary data-entry form → CRITICAL (grade cap D): a user who cannot operate the main path by keyboard or screen reader is locked out of the product, and in the US this is an ADA Title III exposure (note it for Legal).
- A11Y-05 failing on body text or primary actions → HIGH; A11Y-01 with any `critical`-impact axe rule → HIGH. Small-type findings (`text-xs` body copy) are HIGH for this owner even if contrast technically passes.
- Browser/axe results are VERIFIED (100); code greps are READ (85); "shadcn is used so it's probably fine" is INFERRED (50) — only acceptable for A11Y-07 on untouched primitives, and say so.
- Report counts (violations per page, unlabeled controls, undersized targets) next to each status so progress is measurable.
- "To raise confidence": a reachable URL (production or `pnpm dev`) plus a test login for authenticated pages; `pnpm add -D @axe-core/cli` or `@axe-core/playwright` so A11Y-01 can run in CI; a seeded form state to exercise A11Y-14.
