# Copy & Content audit — checks

**Purpose:** Make sure the copy and content are clear and compelling: every word a user or prospect reads is true, plain, consistent, and tells them what to do next.
**Scorecard row:** Copy & Content · **Report:** `audits/copy-content.md` · **Overlaps:** Landing Page (hero/CTA copy — LPO-01/02 own placement, this file owns wording), Legal (disclaimers, regulated wording — Legal owns the requirement, this file flags where copy violates it), Accessibility (link text, alt — WCAG side), Error Handling (which errors exist; this file judges the message text), SEO (title/description text). Reference, don't repeat.

## Inputs to gather first
- Copy corpus: extract user-facing strings — `grep -rhoE ">[^<>{}]{12,}<" app components --include=*.tsx | sed 's/^>//;s/<$//' | sort -u > /tmp/copy.txt`; plus `messages/*.json`/`locales/*.json` if i18n, `content/**/*.{md,mdx}`, email templates (`emails/`, `lib/email/*`), `public/llms.txt`, and the README/docs the product links to.
- Feature inventory from the engineering areas (routes, server actions, tables, integrations) to check claims against.
- Brand voice reference if one exists: `grep -rli "voice\|tone\|style guide" docs content *.md | head`; `.hardbuild.json → audit.brandVoice` (optional free-text) and `audit.primaryCta`.
- Contact facts: the phone, email, address, and company names the owner confirms are current (ask once; do not assume).

## Checks
Format: `ID · weight · check · how to verify (strongest first) · typical failure`

- **CPY-01 · 3 · Claim-vs-code: every promise in UI, marketing, and docs maps to a real feature.**
  VERIFY: build a claims list from the corpus — `grep -rniE "instant|real-?time|automat(ic|ed)|integrat(es|ion) with|supports? (all|every|50 states)|unlimited|guarantee|AI-powered|one-?click|export to|sync(s)? with|SOC ?2|HIPAA|encrypted|24/7|multi-?state|every carrier" app components content emails public --include=*.tsx --include=*.md --include=*.mdx --include=*.txt --include=*.json` → for each claim, name the file:line that implements it (route, server action, table, cron, integration module) or mark it UNBACKED. Common insurance ones: "quotes from N carriers" (count actual rate tables/integrations), "all 50 states" (count state rate files or `states` table rows via Supabase MCP `select count(distinct state) from rates;`), "syncs with your AMS" (an AMS client exists and is called), "real-time FMCSA data" (a scheduled fetch exists and ran recently). List every unbacked claim with `file:line` and the claim text.
  FAIL PATTERN: "Integrates with Applied Epic and AMS360" with no integration code; "Instant bindable quotes" when the flow emails a human underwriter; "Bank-grade encryption" with nothing beyond TLS.
- **CPY-02 · 2 · Reading level is plain; sentences are short.**
  VERIFY: run readability on the extracted corpus — `npx readability-cli /tmp/copy.txt` or `pip install -q textstat && python3 -I -c "import textstat,sys;t=open('/tmp/copy.txt').read();print(textstat.flesch_kincaid_grade(t), textstat.flesch_reading_ease(t))"` → target grade ≤ 9 for marketing/onboarding/microcopy (≤ 12 for underwriting documentation); flag sentences > 25 words (`awk -F'[.!?]' '{for(i=1;i<=NF;i++) if (split($i,w," ")>25) print $i}' /tmp/copy.txt | head`). READ fallback: sample the hero, pricing, onboarding, and three error messages and judge by hand, quoting the worst two.
  FAIL PATTERN: 48-word sentences of stacked nouns ("leverage our comprehensive multi-carrier submission orchestration platform"); jargon unexplained for the stated audience (agents know "mod rate"; PEO prospects may not).
- **CPY-03 · 2 · One term per concept (build a glossary, flag synonyms).**
  VERIFY: from the corpus, `grep -oiE "\b(quote|indication|proposal|estimate|rate)\b" /tmp/copy.txt | tr A-Z a-z | sort | uniq -c`, repeated for other concept clusters — `(client|customer|insured|account|company)`, `(agent|producer|broker|agency|partner)`, `(submission|application|request)`, `(policy|program|plan|coverage)`, `(dashboard|home|overview|workspace)`, `(sign in|log in|login)`, `(sign up|register|create account|get started)`. Each cluster should resolve to one primary term used in nav, headings, buttons, and tables; write the resulting glossary in the report. Also check nav label vs page `<h1>` vs breadcrumb for each route.
  FAIL PATTERN: nav says "Quotes", page title says "Indications", table column says "Proposal #", email says "your estimate"; "Log in" button on a page titled "Sign in".
- **CPY-04 · 2 · Button microcopy is verb-first and specific.**
  VERIFY: `grep -rhoE "<Button[^>]*>[^<]{1,40}<|<button[^>]*>[^<]{1,40}<|type=\"submit\"[^>]*>[^<]{1,40}<" app components --include=*.tsx | sed 's/.*>//;s/<$//' | sort | uniq -c | sort -rn` → flag `Submit`, `OK`, `Yes`, `No`, `Click here`, `Continue` (without context), `Learn more` (as a primary); destructive actions must name the object ("Delete quote", not "Delete"); the primary CTA label equals `audit.primaryCta` everywhere it appears.
  FAIL PATTERN: nine `Submit` buttons across different forms; confirm dialog "Are you sure?" with `OK`/`Cancel`.
- **CPY-05 · 2 · Error, empty, and loading messages are helpful and human.**
  VERIFY: `grep -rnE "Something went wrong|An error occurred|Error:|Unknown error|Oops|Failed to fetch|\[object Object\]|undefined|null\b" app components --include=*.tsx` → generic or leaking messages are findings; each error should say what happened, whether data was saved, and what to do next. Empty states: `grep -rniE "no (data|results|items|records)( found)?\.?<|nothing here" app components` → each should explain why it is empty and offer the first action ("No quotes yet — start one from a submission"). Loading: skeletons or a message for waits > 1 s; no raw spinners on full pages for > 3 s. Error Handling area owns coverage; cite it for which paths lack handling at all.
  FAIL PATTERN: `toast.error(error.message)` surfacing a Postgres constraint name to an agent; empty dashboard that just says "No data".
- **CPY-06 · 3 · No lorem ipsum, placeholder, or "coming soon" text anywhere shipped.**
  VERIFY: `grep -rniE "lorem|ipsum|placeholder text|coming soon|tbd\b|to be determined|\[insert|\[your |\{\{ ?company ?\}\}|todo:|fixme|sample text|dummy|test test|asdf|xxx+" app components content emails public messages --include=*.tsx --include=*.ts --include=*.md --include=*.mdx --include=*.json --include=*.html --include=*.txt -l` then open each hit; exclude legitimate `placeholder=` input attributes and test fixtures under `tests/`/`__tests__`. "Coming soon" is acceptable only on a page that is itself labelled a roadmap/changelog.
  FAIL PATTERN: pricing card "Enterprise — Lorem ipsum dolor"; footer `© {{year}} Company Name`; feature tab "Reports (coming soon)" live for eight months.
- **CPY-07 · 1 · Tone is consistent with the brand voice.**
  VERIFY: READ the brand voice reference (or infer three adjectives from the hero and state them, e.g. "direct, expert, warm"); sample ten strings across hero, pricing, onboarding, empty states, errors, and one transactional email; flag register jumps (hype in the hero, legalese in onboarding, jokes in error states), inconsistent person ("we"/"our team"/"the system"), and inconsistent capitalization style (Title Case vs Sentence case in headings and buttons: `grep -rhoE "<h[1-3][^>]*>[^<]+" app components | sed 's/<[^>]*>//' | awk '{print ($0 ~ /^([A-Z][a-z]+ )+[A-Z][a-z]+$/) ? "TITLE" : "SENTENCE"}' | sort | uniq -c`).
  FAIL PATTERN: "Let's gooo 🚀" success toast in a workers' comp underwriting tool; half the headings Title Case, half sentence case.
- **CPY-08 · 3 · Legal- and compliance-sensitive wording is correct.**
  VERIFY: `grep -rniE "guarantee[ds]? (coverage|approval|savings|rate)|lowest (rate|price)|bindable|bound|binding|you are covered|coverage (is|will be) (in force|effective)|approved|licensed in all|we are (an? )?(carrier|insurer|underwriter)|tax advice|legal advice|free (quote|coverage)" app components content emails` → each hit must be accurate (is the product actually binding, or producing indications?), carry the disclaimer Legal specifies (indication not a quote; subject to underwriting; licensing by state; produced by a licensed agency and its license number where required), and never promise coverage. Testimonials with results need "results vary" where Legal requires. Legal owns the rule set; this check finds the sentences that break it.
  FAIL PATTERN: "Get bound in minutes" on an indications-only flow; "Guaranteed lowest WC rates"; an email footer missing the agency license number in states that require it.
- **CPY-09 · 1 · Spelling and grammar are clean.**
  VERIFY: `npx cspell "app/**/*.{ts,tsx}" "content/**/*.{md,mdx}" "messages/**/*.json" --no-progress --words-only --unique 2>/dev/null | sort -u | head -60` (with a `cspell.json` that includes the glossary from CPY-03 and insurance terms: payroll, mod, NCCI, PEO, EPLI, FMCSA, MGA) → review the list for true misspellings; `npx write-good /tmp/copy.txt | head -40` or `npx alex /tmp/copy.txt` for passive voice/weasel words and insensitive language. READ fallback: proof the hero, pricing, onboarding, and emails by hand; quote each error with file:line.
  FAIL PATTERN: "recieve", "it's" for "its" in the hero; US/UK spelling mixed ("licence" vs "license") in an all-US product.
- **CPY-10 · 1 · Dates, numbers, currency, and percentages are formatted consistently via `Intl`.**
  VERIFY: `grep -rnE "toLocaleDateString\(\)|toLocaleString\(\)|\.toFixed\(2\)\s*\+|'\\$' \+|\`\\$\$\{|new Date\(\)\.toString\(\)" app components lib --include=*.ts --include=*.tsx` → hand-rolled formatting is a finding; expect a shared `lib/format.ts` with `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })`, `Intl.DateTimeFormat`, and percent formatting, used everywhere (`grep -rn "formatCurrency\|formatDate\|formatPercent" app components | wc -l` vs raw hits). Premiums whole-dollar vs cents, dates `MMM d, yyyy` vs `MM/DD/YYYY`, time zones stated for effective dates.
  FAIL PATTERN: `$12500.5` in one table and `$12,500.50` in the PDF; effective date shown as `2026-11-08T00:00:00.000Z`.
- **CPY-11 · 1 · Link text is meaningful.**
  VERIFY: `grep -rniE ">(click here|here|read more|learn more|more|link|this)</?(a|Link)?>" app components content --include=*.tsx --include=*.mdx` → every hit is a finding unless the surrounding sentence is itself the link; external links announce destination ("Read the NCCI class code guide"). Accessibility owns the WCAG 2.4.4 angle; here it is comprehension and scannability.
  FAIL PATTERN: eight "Learn more" cards with identical link text; "click here to download" for the sample report.
- **CPY-12 · 1 · Long-form content has structure.**
  VERIFY: for every `content/**/*.mdx`, docs page, and legal page: `grep -cE "^## " <file>` → ≥ 1 H2 per ~300 words; an intro paragraph that states who the page is for; lists for steps; a table of contents for pages > 1,500 words (`wc -w content/**/*.mdx | sort -rn | head`); no wall-of-text paragraphs > 120 words (`awk 'BEGIN{RS=""} {n=split($0,w," "); if(n>120) print FILENAME": "n" words"}' content/**/*.mdx`).
  FAIL PATTERN: a 3,000-word "How PEO workers' comp works" guide with no headings; Terms of Service as one block.
- **CPY-13 · 2 · Contact and support copy is accurate and real.**
  VERIFY: `grep -rnoE "\(?[0-9]{3}\)?[-. ][0-9]{3}[-. ][0-9]{4}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}|[0-9]+ [A-Za-z ]+ (St|Street|Ave|Avenue|Blvd|Suite|Ste)\.?[^<\"]*" app components content emails public | sort -u` → compare each phone, email, and address with the owner-confirmed facts; `curl -sI mailto` is not possible, so confirm the support mailbox domain has MX records (`dig MX <domain> +short`) and the address appears identically in footer, contact page, emails, Terms, and Privacy. Support hours / SLA statements ("replies within 1 hour") must match reality or be removed.
  FAIL PATTERN: footer phone from a previous company; `support@example.com` left from the template; "24/7 support" for a two-person team.

## Scoring notes
- CPY-01 with any UNBACKED claim about a core capability (binding, carrier count, state coverage, integration, security certification) → CRITICAL (misrepresentation; grade cap D; also file under Legal). CPY-08 with a coverage guarantee or "bound" language on a non-binding flow → CRITICAL. CPY-06 with lorem ipsum or placeholder on a live public page → HIGH (CRITICAL if on pricing or legal pages).
- CPY-13 wrong phone/email → HIGH (lost leads, failed support).
- Deduplicate with Landing Page and Legal: a fabricated testimonial is one finding, filed here with the wording and referenced from LPO-04 and Legal, not three rows.
- Readability tools (CPY-02/09) are supporting evidence; a check PASSes on the audited sample with quoted strings, not on a score alone. A check whose corpus extraction found < 20 strings is INFERRED (50) — say so.
- "To raise confidence": owner-confirmed contact facts and brand voice notes (CPY-07/13); Supabase MCP to count states/carriers/rows behind quantitative claims (CPY-01); a `cspell.json` with the project glossary (CPY-09); the Legal area's disclaimer list (CPY-08); production URL to read rendered copy including CMS-sourced strings not present in the repo.
